# Improvements

Known shortcuts and gaps: what exists, what it should become, and when it becomes worth doing.
The ADR column points to the record that explains the current design.

| Area | Now | Improvement | Worth doing when | ADR |
| --- | --- | --- | --- | --- |
| Configuration | The log level is fixed at `INFO`. | A `LOG_LEVEL` setting. | Someone needs debug logs from a deployed environment. | [0003](adr/0003-api-conventions.md) |
| Database | An unreachable host makes asyncpg wait for its default 60s connect timeout, so `/health` hangs. | Set `connect_args={"timeout": …}` on the engine. | Before deploying. | [0004](adr/0004-database-and-migrations.md) |
| Database | `updated_at` is bumped by SQLAlchemy on ORM updates only; raw SQL updates leave it unchanged. | A `set_updated_at` trigger in the database, created by the migration that adds each table. | The first table is updated outside the ORM. | [0004](adr/0004-database-and-migrations.md) |
| Errors | The users and positions services report any `IntegrityError` on commit as a duplicate (409). A `ck_users_email_lowercase` violation would come back as "email already exists". | Check the violated constraint (`uq_users_email`, `uq_positions_portfolio_id_instrument_id`) and let other integrity errors through as 500s. | A table gets a second constraint the API can trip (the portfolio registration creates belongs to a user just inserted; positions' instrument is looked up before the insert, and the schema keeps the values inside the check constraints). | [0003](adr/0003-api-conventions.md) |
| Errors | OpenAPI still documents FastAPI's default 422 body (`HTTPValidationError`) and no 401/404/409 responses. | Declare `ErrorResponse` in the routes' `responses`. | A client is generated from the OpenAPI schema. | [0003](adr/0003-api-conventions.md) |
| Logging | Nothing checks that logs stay free of sensitive data. The request log has the path only (no query string), and no request bodies or headers are logged. | Review every new log field before it ships, and add a structlog processor that redacts known sensitive keys (`password`, `token`, `authorization`, …). | Before logging query strings, headers or user data. | [0003](adr/0003-api-conventions.md) |
| Decimals | A decimal sent as a JSON number goes through a `float` when FastAPI parses the body, so digits past about 15 significant ones change silently (`"quantity": 1234567890.12345678`). | Parse request bodies with `json.loads(parse_float=Decimal)`, or accept only strings for decimal fields. | Clients send long decimals as numbers. | [0003](adr/0003-api-conventions.md) |
| Pagination | Pages have no total count and no page numbers. | A separate `count` query, or a `total` field computed only when asked for. | The web app needs "page 3 of 12" or a result count. | [0003](adr/0003-api-conventions.md) |
| Auth | Nothing limits how often `/auth/register`, `/auth/login` or `/auth/refresh` can be called. | Rate limiting per IP and per email. | Before the API is reachable from the internet. | [0005](adr/0005-authentication.md) |
| Auth | Email addresses are not verified. | Send a confirmation link; mark the user as verified. | Email sending exists. | [0005](adr/0005-authentication.md) |
| Auth | There is no password reset. | Emailed single-use reset links, revoking all refresh tokens on reset. | Email sending exists. | [0005](adr/0005-authentication.md) |
| Auth | `POST /auth/register` answers 409 for a registered email, so anyone can check whether an address has an account. | Always answer the same way and send a confirmation email instead. | Signup is public. | [0005](adr/0005-authentication.md) |
| Auth | Argon2 hashing (about 40 ms of CPU) runs on the event loop in register and login, blocking other requests meanwhile. | `await anyio.to_thread.run_sync(hash_password, ...)` / `verify_password`. | Login traffic is concurrent enough to show in latency. | [0005](adr/0005-authentication.md) |
| Auth | Logout and reuse detection revoke refresh tokens only; an access token already issued stays valid until it expires (up to 15 minutes). | Check a per-user "tokens valid after" timestamp in `get_current_user`, set on logout-everywhere. | Instant revocation matters (e.g. after a password change or a stolen session). | [0005](adr/0005-authentication.md) |
| Auth | Two refreshes sent at once with the same token (two tabs) look like reuse: the second revokes all of the user's tokens. | A short grace period during which the just-rotated token is still accepted and issues another new pair; it cannot return the same pair, since only hashes are stored. | The web app runs as more than one instance; until then it sends one refresh per token ([web 0001](../../web/docs/adr/0001-auth-through-the-api.md)). | [0005](adr/0005-authentication.md) |
| Auth | Expired and revoked rows stay in `refresh_tokens` forever. | A periodic job deleting rows past `expires_at`. | The table grows noticeably. | [0005](adr/0005-authentication.md) |
| Auth | A failed refresh (401) leaves the stale cookie in the browser. | Clear the cookie on that 401 too. | The web app relies on the cookie's presence. | [0005](adr/0005-authentication.md) |
| Instruments | The search is accent-sensitive: `moet` scores 0.40 against "LVMH Moët Hennessy…" and is not found. | The `unaccent` extension, an `IMMUTABLE` wrapper function around it, and the trigram index on that function of `name`. | Users search names with accents (French, German, Spanish listings). | [0006](adr/0006-instruments.md) |
| Instruments | Name matches use pg_trgm's default word-similarity threshold (0.6): very short typos miss (`aple` scores 0.57 against "Apple Inc."). | Tune `pg_trgm.word_similarity_threshold` with `SET LOCAL` in the search's transaction, checked against real searches. | Users report missing results. | [0006](adr/0006-instruments.md) |
| Instruments | A thin search asks Yahoo every time, with nothing cached: typing a name letter by letter makes one Yahoo request per keystroke past 2 characters. | Cache Yahoo's results per query for a few minutes, and debounce in the web app. | The web app searches as the user types. | [0006](adr/0006-instruments.md) |
| Instruments | A Yahoo result that is stored but did not match the query locally is dropped, not shown as a local result. | Show it as a local result, after the local matches. | Users miss a stored listing that only Yahoo's matching finds. | [0006](adr/0006-instruments.md) |
| Instruments | Yahoo's candidates keep Yahoo's order and always come after every local match, even when Yahoo's first hit fits the query better than a weak local one. | Score Yahoo's candidates with `word_similarity` like local names, and merge both lists by score, keeping exact ISIN and symbol-prefix matches first. | Users report the right listing appearing below poorer ones. | [0006](adr/0006-instruments.md) |
| Instruments | Instruments stored without a FIGI (OpenFIGI down or no single match, logged as `instruments.figi_missing`) are never retried, so they stay ungrouped. | A backfill command that looks up `share_class_figi` for every instrument where it is null. | Ungrouped listings show up in a portfolio, or OpenFIGI was down during an import. | [0006](adr/0006-instruments.md) |
| Instruments | `POST /instruments/resolve` returns a stored symbol as it is: an `isin` passed with it is ignored, even when the stored row has none (`find_instrument_by_isin` fills it). | Fill `isin` there too, with the same `UPDATE … WHERE isin IS NULL`. | Clients resolve stored symbols with an ISIN. | [0006](adr/0006-instruments.md) |
| Instruments | `yahoo_symbol`, `exchange_code` and `currency` are uppercase only because the writer normalizes them; the database accepts `mc.pa` next to `MC.PA`, or `GBp`. | `CheckConstraint`s such as `currency ~ '^[A-Z]{3}$'` and `yahoo_symbol = upper(yahoo_symbol)`, like `ck_users_email_lowercase`. | Search and import start writing instruments. | [0006](adr/0006-instruments.md) |
| Instruments | `ck_instruments_isin_format` checks the shape of an ISIN only; the check digit is validated by the `Isin` schema alias, so a row written outside the API can hold `FR0000121015`. | A `CHECK` calling an `IMMUTABLE` SQL function that computes the check digit. | Instruments are written outside the API. | [0006](adr/0006-instruments.md) |
| Instruments | The exchange order for an ISIN without a home exchange (Paris, Amsterdam, Xetra, London, US, Hong Kong) is a constant, suited to a euro investor. | A per-user preferred order, or one derived from the user's currency. | A user outside the eurozone imports funds. | [0006](adr/0006-instruments.md) |
| Instruments | `find_instrument_by_isin` checks listings against Yahoo one after another (up to 5, about half a second each). | Check them concurrently and keep the first in exchange order. | Imports of many ISINs feel slow. | [0006](adr/0006-instruments.md) |
| Market data | Only pence (`GBp`, `GBX`) are converted. Other minor units Yahoo uses, such as South African cents (`ZAc`) and Israeli agorot (`ILA`), pass through as the currency. | Map them to `ZAR` and `ILS` with a factor of 0.01. | A Johannesburg or Tel Aviv listing is added. | [0007](adr/0007-market-data.md) |
| Market data | A rate limit or network error answers 503 at once; nothing retries. | Retry with backoff in the client for `YFRateLimitError` and connection errors. | The daily price job hits rate limits. | [0007](adr/0007-market-data.md) |
| Market data | yfinance's own timeouts apply (30 s for a search), each holding a worker thread while it waits. | Pass a shorter `timeout` to yfinance. | An endpoint calls Yahoo while a user waits. | [0007](adr/0007-market-data.md) |
| Market data | Prices are rounded to 4 decimal places in Yahoo's unit, so a listing priced below 0.0001 would lose precision. | Round to significant digits (float32 keeps about 7) rather than a fixed number of places. | A listing trades below 0.01. | [0007](adr/0007-market-data.md) |
| Market data | `get_details` answers `None` both for a symbol Yahoo does not know and for one it knows with an unsupported quote type (an index such as `^GSPC`), so a caller cannot tell the user which. | Return the details with Yahoo's quote type for every known symbol, and let the caller reject unsupported types. | The user is shown why a symbol cannot be added. | [0007](adr/0007-market-data.md) |
| Prices | Running `backfill` again rewrites every stored bar, even unchanged ones, leaving a dead row version per day for vacuum. | Add `WHERE (open, high, low, close, adj_close, volume) IS DISTINCT FROM (excluded.…)` to the `DO UPDATE`. | Backfills run routinely (e.g. after each split). | [0007](adr/0007-market-data.md) |
| Prices | A range is capped at 1,830 days of daily bars, so a chart of a full history takes several requests. | Weekly or monthly bars aggregated in SQL for long ranges. | The web app shows a "max" chart. | [0007](adr/0007-market-data.md) |
| Prices | `update_prices` runs only when someone types `just update-prices`. | A scheduler (cron, or a container on a timer) running it once a day after the markets close. | Prices must stay current without anyone running the job. | [0007](adr/0007-market-data.md) |
| Prices | A split stays in the 5-day window for up to 5 runs, and the instrument's full history is fetched again on each one. | Remember the splits already handled (a `splits` table, or the date of the last backfill) and backfill only for a new one. | Splits are common among followed instruments, or the job runs more than once a day. | [0007](adr/0007-market-data.md) |
| Prices | The job exits with status 0 even when symbols failed; only its log line says so. | Exit with a non-zero status when `failed` is not empty. | A scheduler runs the job and should alert on failures. | [0007](adr/0007-market-data.md) |
| Prices | Backfills run one after another (about a second each), so the first run with many followed instruments is slow. | Fetch the histories concurrently, then write them one at a time. | Dozens of instruments are added at once (the CSV import). | [0007](adr/0007-market-data.md) |
| Prices | `to` defaults to the server's date, not the exchange's, so around midnight it can be a day off. | Default to the exchange's date from its time zone. | The server and the exchanges are in different time zones. | [0007](adr/0007-market-data.md) |
| FX rates | Rates start from the first `update_rates` run (5 days back): an amount at an earlier date has no rate, and the overview reports its position as `no_rate`. | Fetch a currency's full history (`get_history` without `start`) the first time it is held, as `backfill` does for prices. | Values or performance are shown at dates before the first run. | [0007](adr/0007-market-data.md) |
| FX rates | `get_rate` uses the latest rate on or before the date however old it is, so a currency whose updates keep failing converts at a stale rate without saying so. | Stop looking back after a few days and return `None`, or return the rate's date with the rate. | The job runs on a schedule, or totals are shown to someone who acts on them. | [0007](adr/0007-market-data.md) |
| FX rates | `fx_rates` has no base currency column: after `BASE_CURRENCY` changes, the rates stored under the old base stay and `get_rate` uses them. | A `base` column in the key, or a check at startup that refuses rates of another base. | The base currency changes on a database that already has rates. | [0007](adr/0007-market-data.md) |
| Identifiers | Share-class tickers are not converted: Yahoo writes `BRK-B` and `BT-A.L`, Bloomberg `BRK/B` and `BT/A`. | Convert `-` and `/` between the two in the exchange map's ticker functions. | A holding has a share-class ticker. | [0008](adr/0008-security-identifiers.md) |
| Identifiers | The exchange map covers 9 Yahoo suffixes; listings elsewhere (`.MI`, `.MC`, `.TO`, …) get no share class FIGI. | Add their Bloomberg codes (IM, SM, CT, …), checked against OpenFIGI like the current ones. | A holding is listed on another exchange. | [0008](adr/0008-security-identifiers.md) |
| Identifiers | A 429 waits as long as its `Retry-After` asks (up to 60 s) inside the call. | Fail fast with a 503 when a user is waiting, and keep the wait for background jobs. | An endpoint calls OpenFIGI. | [0008](adr/0008-security-identifiers.md) |
| Portfolios | Only registration creates a user's portfolio; a user inserted any other way has none, and every `/portfolio` route answers 500 for them. | Create it on first use, with `INSERT … ON CONFLICT (user_id) DO NOTHING`, then read it. | Users are created outside `/auth/register` (an admin command, single sign-on). | [0009](adr/0009-portfolios.md) |
| Portfolios | The overview converts a position's cost at the rate of its latest close, so in the base currency its unrealised gain shows the price's move only, not the currency's since the purchase. | Convert the cost at the purchase date's rate, which needs dated purchases. | The user holds enough foreign currency for currency moves to matter. | [0009](adr/0009-portfolios.md) |
| Imports | The import runs within the request: each new ISIN costs two OpenFIGI requests and up to 5 Yahoo checks, so without an OpenFIGI key (25 requests a minute) about 12 new ISINs take a minute. | Run the import as a background job and let the client poll its report. | Imports of more than a few dozen new ISINs, or a proxy timeout in front of the API. | [0009](adr/0009-portfolios.md) |
| Imports | The 64 KiB limit is checked after Starlette has received the whole upload and spooled it to a temporary file. | Limit the request body size at the reverse proxy, or in a middleware that stops reading past it. | Before the API is reachable from the internet. | [0009](adr/0009-portfolios.md) |
| Imports | OpenFIGI or Yahoo failing during an import answers 503: the rows before it stay imported, and their report is lost (importing again is safe). | Report the remaining rows as `unavailable` and return the report. | Imports fail on provider outages users notice. | [0009](adr/0009-portfolios.md) |
| News | Google News RSS is the only source. | Finnhub company news as a second `NewsSource`, queried with a group's US or Canadian listing, or with a foreign company's US ticker (`TM` for 7203.T) from a hand-kept map. Its tags are loose, so its links need the model's confirmation (below). | Google's recall for a followed security is poor, or US holdings need ticker-tagged news. | [0010](adr/0010-news-ingestion.md) |
| News | A 429, a 5xx or a timeout from Google News fails the search at once; nothing retries. | Retry once after a few seconds, honouring `Retry-After`, as the OpenFIGI client does. | Runs lose groups to transient Google errors. | [0010](adr/0010-news-ingestion.md) |
| News | GDELT, publisher RSS feeds and Yahoo search news are not used. | Each as its own `NewsSource`; publisher feeds need name matching (below). Yahoo only for US listings. | Coverage of a market stays thin after Finnhub. | [0010](adr/0010-news-ingestion.md) |
| News | Each group is queried with one name, its first-stored listing's minus the legal form; long official names ("LVMH Moët Hennessy - Louis Vuitton", "ASML Holding") find little as an exact phrase. | A hand-kept `aliases.toml`, keyed by Yahoo symbol, with the names the press uses ("LVMH", "Louis Vuitton"; "Alphabet", "Google"; "TSMC"), each queried and each accepted by the off-topic check, which now takes only the first word of the news name. | A followed security's query returns few articles, or its headlines are dropped as `off_topic` because the press uses another name. | [0010](adr/0010-news-ingestion.md) |
| News | Finance terms in the query miss material stories without finance words (Reuters on Toyota and Waymo's robotaxi deal). | Also run the plain name query and keep its results from tier 1 publishers, or let the model judge relevance on them. | The evaluation finds missed stories that matter. | [0010](adr/0010-news-ingestion.md) |
| News | An article is linked only to the group whose query found it. | Name matching (names on word boundaries, explicit ticker forms such as `(EPA: MC)`) of every article against every followed security, with a `method` per link, and the model confirming each link as `primary`, `secondary` or `none`. | A second source arrives, or untargeted feeds are added. | [0010](adr/0010-news-ingestion.md) |
| News | A listing followed later has no links to articles fetched before it. | Link the group's stored articles when an instrument is followed, or read news through `share_class_figi`. | A user follows a second listing of a security and misses its earlier news. | [0010](adr/0010-news-ingestion.md) |
| News | All publishers count the same; only a short excluded-domain list in code ranks them. | A `publishers.toml` of domains and tiers (wires and leading financial press, general press, aggregators) that picks the copy kept among duplicates and orders the brief's input. | Briefs lean on low-quality publishers. | [0010](adr/0010-news-ingestion.md) |
| News | Google's redirect links are stored as-is, so URLs are not normalised and the same article under two tokens is caught only by its title. | Decode the links (filtering by the item's publisher first to save requests to the endpoint that rate-limits), follow redirects, prefer `<link rel="canonical">`, strip tracking parameters (courlan). | Article text is needed, or duplicates under different links slip through. | [0010](adr/0010-news-ingestion.md) |
| News | Duplicates are caught by URL and by the same normalised title only. | Trigram similarity of `title_key`s at least 0.9 within 48 hours (pg_trgm), with pairs between 0.6 and 0.9 logged to tune it, and a hash of the extracted text for syndicated wire copy. | Reworded duplicates show up in the news list or crowd a brief's input. | [0010](adr/0010-news-ingestion.md) |
| News | `title_key` folds accents with Unicode NFKD, which leaves letters that do not decompose unchanged: "Ørsted" gives `ørsted`, "Orsted" `orsted`, so the two copies are not merged. | Transliterate with `anyascii` before casefolding. | Duplicates that differ only by such letters (ø, ł, æ, đ) reach the news list. | [0010](adr/0010-news-ingestion.md) |
| News | `articles.url` and `title_key` are `text` with no length limit, but a B-tree index entry holds at most about 2,700 bytes, so a longer value would fail its insert. | `max_length` on `RawArticle`'s `url` and `title`, dropping the article when it is over. | A source returns URLs or titles of more than a few hundred characters. | [0010](adr/0010-news-ingestion.md) |
| News | Briefs are written from headlines only; no article text is fetched. | Fetch pages (robots.txt, per-domain rate limits, a size cap), extract text with trafilatura, mark paywalled pages without bypassing them, keep text 30 days, and summarise each article before the brief. | Headline-only briefs prove too thin in the evaluation. | [0010](adr/0010-news-ingestion.md) |
| News | `just ingest-news` and `just brief` run only when typed, and nothing stops two runs overlapping; two overlapping ingest runs can store the same headline twice, since the duplicate-title check is a read before the insert. | A scheduler process (APScheduler 3.x, `python -m app.jobs.scheduler`) running prices and news, with a `job_runs` table, a Postgres advisory lock per job, and catch-up of missed runs at start. | News and prices must stay current without anyone running the commands. | [0010](adr/0010-news-ingestion.md) |
| News | Each run queries `when:1d`, so days without a run are lost. | Set `when:` from the time since the group's last successful fetch, up to `7d`. | Runs are often more than a day apart. | [0010](adr/0010-news-ingestion.md) |
| News | Nothing caps model spend beyond what the commands make. | A run cap on calls and a `BRIEF_MONTHLY_BUDGET_USD` checked against stored token counts. | Briefs run unattended on a scheduler. | [0010](adr/0010-news-ingestion.md) |
| News | News is shown only in the app. | A daily or weekly digest per user (`digest_frequency`), stored in a `digests` table and sent over SMTP (Mailpit in development), or pushed through ntfy or Telegram. | The user wants news without opening the app; needs the scheduler. | [0010](adr/0010-news-ingestion.md) |
| News | News is read per instrument only. | `GET /news` over every followed security, keyset-paginated with `paginate(..., order_by=Article.published_at)`. | The web app gets a home feed. | [0010](adr/0010-news-ingestion.md) |
| News | `GET /instruments/{id}/news` has no index on `(published_at, id)`: Postgres finds the share class's articles through `article_instruments` and sorts them. 30 days of retention keeps that to a few hundred rows. | An index on `articles (published_at, id)`, checked with `EXPLAIN` against the link lookup. | A share class has thousands of stored articles. | [0010](adr/0010-news-ingestion.md) |
| News | A brief whose cited articles were deleted (published more than 30 days ago) still answers, with "From 0 articles" in its provenance line and no citations. | Store the citation count on the brief, or stop serving a brief once its period is older than the retention. | Securities go a month without news while their old brief is still read. | [0010](adr/0010-news-ingestion.md) |
| News | A group gets a new brief only for an article published after its latest brief's newest headline; one Google indexes late, published before that, waits for the next newer article. | Compare the time each link was added (`article_instruments.created_at`) with the brief's `generated_at`. | Late-indexed stories go missing from briefs for long. | [0010](adr/0010-news-ingestion.md) |
| News | Forecasts and price targets in the brief's own voice ("the stock will rise", "a price target of $250") are forbidden by the prompt only: the deny-list keeps to second person and advice, since a phrase cannot tell the brief's voice from a reported one. Sentence count is not checked, only length. | Attribution-aware checks (a claim's sentence names an outlet), or the model judging its own draft against the rules. | The evaluation finds forecasts in the brief's own voice. | [0010](adr/0010-news-ingestion.md) |
| News | A group whose new headlines have nothing about the business stores no brief, so each run asks the model again about the same headlines until a newer one arrives or they leave the 3-day window. | Record the newest headline checked per group (a `no_news` brief row, or a column on a group table) and compare against it. | Runs are frequent enough for the repeated calls to cost something. | [0010](adr/0010-news-ingestion.md) |
| News | A brief can name an outlet whose headline it does not cite (Stock Titan in TotalEnergies' first brief, Simply Wall St in ASML's), so its provenance line misses a source. | A check that every publisher named in the text is the publisher of a cited headline. | Briefs often name outlets they do not cite. | [0010](adr/0010-news-ingestion.md) |
| News | The CLI backend counts as available when `claude` is on the PATH, logged in or not; a logged-out CLI fails each group with "not logged in" instead of skipping the run. | Check the login once before the run (a status command, or stop at the first `NOT_LOGGED_IN`) and skip with that reason. | The CLI is often installed but logged out where briefs run. | [0011](adr/0011-local-llm-backend.md) |
| News | Token counts from the CLI include its own context (13,778 input tokens for a brief the API wrote with 5,314), and the run sums them with the API's in the same fields. | Store the CLI's counts apart, or not at all, and estimate cost only from API briefs. | Costs are tracked across backends. | [0011](adr/0011-local-llm-backend.md) |
| News | `InvalidOutputError` carries no token counts, so the cost of rejected answers is not recorded. | Attach the response's usage to the error and add it to the run's totals. | Rejected answers become frequent enough to matter in the cost. | [0010](adr/0010-news-ingestion.md) |
| News | ETFs get no news. | Their index's or issuer's headlines. | A user wants news on the ETFs they hold. | [0010](adr/0010-news-ingestion.md) |
